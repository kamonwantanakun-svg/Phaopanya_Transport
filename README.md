## ⚠️ เกณฑ์สำคัญที่สุด: ตารางจริง (29) กับ ตารางบอท (61)

นี่คือข้อเท็จจริงเชิงโครงสร้างที่สำคัญที่สุดของรีโปนี้ ถ้า AI ไม่รู้เรื่องนี้
มันจะเสนอให้แก้ตารางที่แก้ไม่ได้ หรือนับตารางผิด

| | **ตารางจริง (29 ตาราง)** | **ตารางบอท (61 ตาราง)** |
|---|---|---|
| ที่มา | ผูกกับ worksheet ใน Google Sheet | AppSheet สร้างขึ้นเอง (`Data Source = native`) |
| `Source Path` | ชี้ไปที่ชีตของแอป | `/ProcessStateTables/…` หรือ `…/StepOutput_…` |
| `Visible?` | `ALWAYS` — เห็นในเมนู | `NEVER` — มองไม่เห็น |
| ใช้ทำอะไร | ข้อมูลธุรกิจที่คนกรอก | state ของ bot process + ผลลัพธ์ของแต่ละ step |
| แก้ได้ไหม | ✅ ได้ | ❌ **ห้ามแก้** — ปล่อยให้ AppSheet สร้างใหม่ |
| มีวิว/แอคชันผูก | ครบ 29 ตาราง | **0 ตาราง** (ไม่มีวิวหรือแอคชันไหนอ้างถึงตารางบอท) |

ตารางบอท 61 ตาราง แบ่งเป็น **30 process** (bot app เดียวกัน `70999aca-…`):

- `process-state` 30 ตาราง — state ของแต่ละ process
- `process-output` 30 ตาราง — ผลลัพธ์ของแต่ละ step
- `per-user-settings` 1 ตาราง — `_Per User Settings` (ค่าตั้งรายผู้ใช้)

จับคู่ process ↔ state table ↔ step output ได้ที่ `[data/references/processes.csv]`

## 💡 ข้อแนะนำสำหรับ AI ที่จะช่วยวิเคราะห์

1. **อ่าน `docs/09-glossary.md` ก่อน** — ชื่อคอลัมน์เป็นภาษาไทยทั้งหมด ถ้าไม่รู้ศัพท์จะตีความผิด (`วางบิล` = invoice, `เบิกส่วนต่าง` = claim difference, `เรทดีเซล` = diesel rate, `JWD` = just-in-way-delivery ของ SCG)
2. **แยกตารางจริง/บอทก่อนเสนอคำแนะนำ** — 61 ตารางบอทแก้ไม่ได้ (ดูหัวข้อเกณฑ์ข้างบน)
3. **ใช้ `doc_page` ยืนยัน** ก่อนเสนอว่าสูตรผิด — ค่าที่ขึ้นบรรทัดอาจดูเหมือนผิดแต่ไม่ได้ผิด
4. **`digest/` คือข้อมูลแบบอ่านเร็วที่สุด** — เริ่มจากตรงนั้น แล้วค่อยเจาะ `data/` เมื่อต้องการรายละเอียด
5. **อ้างที่มาของตัวเลขทุกครั้ง** — ทุกไฟล์ใน `data/` มี `doc_page` ชี้หน้าจริงใน PDF ต้นฉบับ
6. **ถ้าจะเสนอการเปลี่ยนแปลง ให้บอกด้วยว่าแก้ที่ตาราง/คอลัมน์ไหน และกระทบอะไร** — เช่น `ข้อมูลการวางบิล.ราคา` เป็น *Initial value* ไม่ใช่คอลัมน์คำนวณ
   → ถ้าผู้ใช้แก้ `เรทดีเซล` หลังสร้างแถว ราคาจะไม่อัปเดต (ดู `docs/10-known-issues.md`)
