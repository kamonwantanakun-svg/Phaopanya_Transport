## 3. ตารางสัญญาณสีที่ผู้ใช้ต้องจำ

| สี/สัญลักษณ์ | ความหมาย | มาจากกฎ |
|---|---|---|
| 🟢 เขียว + ✓ | อนุมัติแล้ว | `อนุมัติ` |
| 🟠 ส้ม + ⏰ | รอการอนุมัติ | `รอการอนุมัติ` |
| 🔴 แดง (ราคาไม่ตรง) | ราคาในระบบ ≠ ราคาจริง → ต้องตรวจ | `แจ้งเตือนราคาหลังวิ่งงาน` + สไลซ์ `View ราคาไม่ตรง` |
| 🟢 เขียว (ราคาตรง) | ราคาตรงกัน ปกติ | `แจ้งเตือนเช็คราคาแล้วปกติ` |
| 🟢 เขียว + 💰 | เบิกส่วนต่างได้ (ค่าส่วนเพิ่ม > 0) | `ทำเบิกได้` |
| 🔴 แดง ขีดฆ่า | เบิกไม่ได้ (ค่าส่วนเพิ่ม < 0 = ต้องคืนเงิน) | `ทำเบิกไม่ได้` |
| 🔴 แดง (Shipment No) | งานนี้อยู่ในรายการ RW → ต้องเช็ค | `เตือนตรวจสอบ RW` |
| 🟢 เขียว + ✓ (แถวงาน) | สแกนแล้ว | `Green_Done` |
| 🟢 เขียว (Invoice No) | สแกนรับแล้ว | `สแกนรับแล้ว` |
| 🔴 แดง (Invoice No) | รอสแกน | `รอสแกน` |
| 🔴 พื้นแดง (5 คอลัมน์) | ผลตรวจสอบงานส่ง = FAIL | `ผลการตรวจสอบงานส่ง_FAIL` |

### 3.1 ข้อสังเกตสำคัญ: กฎ 8 กับ 10/11 ใช้ค่าคนละคำ

| กฎ | เงื่อนไข | ค่าที่เทียบ |
|---|---|---|
| `Green_Done` | `=[ScanStatus] = "สแกนแล้ว"` | **“สแกนแล้ว”** |
| `สแกนรับแล้ว` | `=[ScanStatus] = "สแกนรับแล้ว"` | **“สแกนรับแล้ว”** |
| `รอสแกน` | `=[ScanStatus] <> "สแกนรับแล้ว"` | **“ส่วนรับแล้ว”** |

ค่า Enum จริงของ `ตารางงานประจำวัน.ScanStatus` (จาก PDF หน้า 157) คือ
`รอสแกน`, `คลังตัดสินค้า`, `สแกนรับแล้ว`

→ กฎ `Green_Done` เทียบกับค่า `สแกนแล้ว` ซึ่ง **ไม่อยู่ในรายการ Enum ที่ PDF พิมพ์ไว้**
จึงมีแนวโน้มไม่ทำงาน — เป็นจุดที่ควรตรวจในแอปจริง (ดู `10-known-issues.md`)
