## 1. สองประเภทตาราง — แยกอย่างไรไม่ให้พลาด

### 1.1 เกณฑ์และหลักฐาน

| เกณฑ์ | ผล | จำนวน |
|---|---|---:|
| `Data Source` = `google` | ตารางจริง — ผูกกับชีตใน Google Sheet | 24 |
| `Data Source` = `google_tables` | ตารางจริง — ผูกกับตารางในฐานข้อมูลของแอป (AppSheet Tables) | 1 |
| `Data Source` = `native` | **ตารางบอท** — ไม่มีชีตเบื้องหลัง | 61 |

ตารางบอทยืนยันซ้ำด้วย `Source Path` 3 แบบ: ขึ้นต้นด้วย `/ProcessStateTables/`, มี `/StepOutput_`,
หรือชื่อว่า `_Per User Settings` — ทั้งหมดใน `[data/tables/index.csv]`

> **หมายเหตุ:** `ตารางงานประจำวัน`, `ข้อมูลชื่องานต้นทางปลายทาง`, `ทำเบิกส่วนต่างScgวังน้อย`,
> `สรุป_เจ้าของสินค้า` มีค่า `Data Source` **ว่างเปล่า** ในไฟล์ แต่เป็นตารางจริง เพราะ
> `Source Path` ชี้ไปที่ชีต/โฟลเดอร์แอป และ `Worksheet Name/Qualifier` เท่ากับชื่อตารางเอง
> — `[data/tables/index.csv]` (ดูหัวข้อ 4.5 ใน `10-known-issues.md` ว่าค่านี้หายจาก PDF อย่างไร)

## 3. ตารางบอท 61 ตารางเชื่อมกับตารางจริงอย่างไร

### 3.1 โครงสร้าง

Automation/Bot แอปหนึ่งตัวคือ `70999aca-5a1f-4dfc-907b-417bc046f574` ภายในมี **30 process**
(แยกด้วย UUID ระดับที่สองใน `Source Path`) — `[data/references/processes.csv]`

```
process UUID
 ├── State Table      → เก็บ "บอทตัวนี้ทำงานถึงขั้นตอนไหนแล้ว" + ตัวแปรของบอท
 └── StepOutput_<ชื่อ step> → ผลลัพท์ที่ step ส่งต่อให้ step ถัดไป (0–3 ต่อ process)
```

- 30 State Table + 30 Step Output + `_Per User Settings` 1 = **61**
- 22 process มี 1 output · 1 process มี 2 output (`AppSheet_KM - 1`) ·
  2 process มี 3 output (`ทำเบิกส่วนต่างScgวังน้อย - 1`, `Bot_เบิกค่าขนส่งตามระยะทาง - 1`) ·
  5 process ไม่มี output — `[data/references/processes.csv]`

### 3.2 จุดเชื่อม: State Table กับ Step Output

คอลัมน์ท้ายสุดของ State Table ชี้ไปยัง Step Output ของ process ตัวเอง (คอลัมน์ `binding_column`)
— ตรวจได้จาก `[data/references/processes.csv]` เช่น

|---|---|
| `ปริ๊นใบวางบิล` | `ปริ๊นใบวางบิล_step` → `ปริ๊นใบวางบิล_step Output` |
| `ทำเบิกส่วนต่างScgวังน้อย - 1` | `ทำเบิกส่วนต่างScgวังน้อยstep` · `New step2` · `ไม่ผ่านNew step` |
| `Bot_เบิกค่าขนส่งตามระยะทาง - 1` | `เบิกตามระยะทาง` · `New step4` · `New step3` |

## 4. สรุปสำหรับผู้วิเคราะห์ข้อมูล

1. **แก้ได้แค่ตารางจริง 29 ตาราง** — ตารางบอท 61 ตารางคือ state/output ของบอท (`READ_ONLY`, `NEVER`)
2. **แกนข้อมูล 3 ตาราง**: `ตารางงานประจำวัน` (งาน) → `ข้อมูลการวางบิล` (เงิน) →
   `SCGนครหลวงJWDภูมิภาค` (หลักฐานการส่งจริง) และ `ทำเบิกส่วนต่างScgวังน้อย` (ผลลัพธ์ส่วนต่าง)
3. **เชื่อมตารางด้วย 3 คีย์หลักเท่านั้น**: `Shipment No`, `Invoice No`, `ID_พนักงาน`/`Email พนักงาน`
   (+ `จุดส่งสินค้าปลายทาง` สำหรับงานเบิกส่วนต่าง)
4. **ราคาไม่ได้อยู่ที่เดียว** — มี 4 แหล่ง: `Price_Table` (เรท×ระยะทาง), `PriceOverride` (ทับเป็นช่วงวันที่),
   `ราคาน้ำมันดีเซล` (รายวัน), `ราคาในระบบก่อนส่งสินค้า` (ราคาจริง) — ต้องรู้ว่ากำลังดูอันไหน
5. **ระบบเอกสารใช้คีย์ “ชื่องาน + ช่วงวันที่”** ไม่ใช่ ID เดียว — กรองด้วย `FILTER` เสมอ
